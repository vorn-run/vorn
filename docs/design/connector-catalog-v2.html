Vorn · design note

Rows, not cards

The card grid was the wrong shape. I went and looked at four catalogs people actually like, and three of them are a single column of rows. The fourth is a marketing page with four columns of screenshots and no idea which integrations you already use.

What the good ones do

Nobody puts a card grid in a settings panel

Catalog Shape What a row carries
Raycast Store One column of rows 64px icon, name, one-line description, author with avatar, then plain facts — “8 Commands”, “502,900” — and one Install button
VS Code Extensions One column of rows Name, publisher, one-line description, downloads, rating, and a right-aligned Install — which becomes a gear once installed
GitHub Marketplace One column, generous spacing Logo, name heading, one line of 80–120 characters. Categories live in a sidebar
Linear integrations Four-column card grid Icon, name, “By …”, one line. A marketing page — it does not show which ones you have connected at all

Three things fall out of that, and my mockup got all three wrong.

  • Rows, not cards. A settings panel is narrow. Two columns of cards halves the width available for a description and doubles the chrome around it. Every catalog built for a panel uses full-width rows.
  • Facts as plain text, not coloured pills. Raycast writes “8 Commands”. I wrote a cyan pill, an amber pill and a green pill, on every card. Colour stops meaning anything when everything has some.
  • Filters get out of the way. GitHub uses a sidebar, VS Code a dropdown and search tokens. I used a row of chips that wraps to two lines and pushes the content down.

Your connections

What you run, with what it is doing

The connector is the row; its connections nest under it. One heading per kind, indented rows for the instances — which is the only place a count belongs, next to the things it counts.

Browse

One column, one action, no confetti

The same row shape, so the eye does not have to relearn the page. Facts in one muted line the way Raycast writes them. One button on the right, which says Add or, for something you already use, Add another — the only distinction that needs making.

Detail

The list gets out of the way

Both references open a page, not a panel wedged under a grid. Clicking a row replaces the list, with a way back. Nothing reflows, nothing has to fit beside anything else, and it reads the same at any width.

What changes from the last note

The split stands; the shape does not

  • Kept: connections and connectors are different nouns and never share a list; installedListings goes away; a card says “in use” rather than repeating the connections above it; sign-in failure moves into the row it concerns.
  • Changed: one column of rows instead of a card grid. Facts as one muted line instead of three coloured pills. A category dropdown instead of a wrapping chip row. Detail replaces the list instead of appearing beneath it. A segmented control makes the two nouns switchable rather than stacked, so neither is a wall you scroll past.

The data layer built for the last version does not change at all — listingDetails, the catalog fetch, the freshness line and their tests are all still right. This is a rewrite of two components.
